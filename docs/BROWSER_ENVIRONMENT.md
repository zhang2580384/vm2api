# 槽位浏览器环境管理

## v2.4.2 · r5 原生人工授权与浏览器保留

显式点击「登录」或「打开远程浏览器」时，在选中槽位内直接启动 Chromium，以私有 Xvfb 提供画面，以 X11/XTEST 传递人工鼠标键盘；该窗口不连接 Playwright、CDP 或浏览器调试端口。远程画面包含浏览器地址栏和标签页。沿用槽位的网络、代理出口、语言、时区和账号隔离 profile，不把会话搬到面板机或本机客户端，不覆盖浏览器指纹属性。无 GPU 时禁用硬件 GPU 合成以保证远程画面可见；没有伪造 GPU 或 WebGL 信息。

运行包新增固定版本 `python-xlib==0.33`，修订号升为 r5。点击登录时自动检测和准备匹配运行包，旧 r4 包会升级；首次安装仍需构建或下载依赖，已有 SHA-256 校验缓存可以复用。面板安装状态显示是否具备原生操控组件。

人工完成网页授权后，槽内回调监听器只在 `127.0.0.1:1455` 接收指定路径，并核对随机 state；后台立即按原有 PKCE 流程换取授权，确认账号身份后保存凭据。授权成功后保留同一个浏览器进程、私有显示和 profile，远程画面继续可用，不自动关闭或卸载。一次性回调端口随即释放，后续关闭窗口、取消或浏览器异常不会把已保存的授权改成登录失败。此行为替代 v2.4.1 的成功后自动卸载。

可继续在原窗口处理续费、领取活动权益等人工操作。「Session 页面」打开 `https://chatgpt.com/api/auth/session`；网页已登录时，可在远程画面按 Ctrl+A、Ctrl+C，再使用「读取远程剪贴板 / 复制到本机」导出。该入口不调用第三方服务，不自动读取或持久化 Session；Codex OAuth 授权本身不保证 ChatGPT 网页会话已登录。

「关闭浏览器」只停止进程并恢复临时资源，浏览器环境和会话资料继续保留；关闭后可按需点「卸载浏览器环境」节省槽位磁盘。手动窗口及授权完成后的窗口不按空闲时间关闭，离开详情页不停止窗口，可返回后重新连接。浏览器打开期间持续占用运行资源及全局浏览器任务锁；服务重启、槽位关机、配置变更或显式停止仍会终止进程。未完成授权的登录超时及后台自动重登的退出行为保持。

现有自动注册流程和后台凭据失效后的自动重登仍保留原实现；注册完成后的 OAuth 确认窗口采用原生人工授权。导入、绑定凭据均不会登录；静置槽位允许显式手动操作，不开启调度。全局同时只运行一个浏览器或维护任务，其他请求返回忙碌，目前没有排队机制。

原生窗口、图形环境和输入正常不代表第三方人机验证一定通过。上述改动不自动处理验证码，也不保证消除验证循环。

## v2.4.0 图形环境状态核验

v2.4.0 面板显示 Playwright 版本及运行包修订号（如 `1.64.1 · r4`），并检查图形二进制的执行权限。旧包或组件不可执行时明确提示升级；登录缺少有效显示地址时停止。该版本的控制面升级与槽位运行包升级是两个步骤，升级保留 profiles、缓存和配置。r5 改为登录时按需准备。

图形运行包的构建和安装修复自 v2.1.2 已进入公开镜像；本次直接检查 v2.1.2、v2.3.0 amd64 镜像中的 7 个关键文件，均与相应 Git 标签一致。大型运行包通过安装按钮按匹配系统构建、校验和缓存。确认 r4 图形模式后仍反复遇到 CF 验证，应结合实际出口、网络和会话排查，不能仅凭循环验证认定组件未发布。

## v2.1.2 图形运行包升级

旧 r3 包没有包含标准图形环境。v2.1.2 引入 r4 图形包，当时需要在槽位详情手动升级；r5 延续其便携图形组件并增加原生输入。图形组件从匹配发行版的官方源码构建，并以槽位用户运行，不写入只读系统目录。安装前使用相同显示模块在临时目录验证图形启动、截图及点击，失败不覆盖旧包。卸载包含图形组件，profiles、缓存和配置仍保留。

r5 的 Docker 浏览器任务会在执行前临时将低于 1.5 GiB 的有限内存上限提高到 1536 MiB，并处理配套 swap 上限；更高或无限的原内存设置保持。CPU 临时限制为最多 1 核，原有更严格限额保持。任务退出、浏览器进程清理完成后恢复原限制，不重建槽位、不改写持久规格、不改变调度。这个值是整个槽位的容器上限，不是额外分配 1.5 GiB，也不是宿主机物理内存预留或任何网页负载下的无 OOM 保证。手动安装环境仍应为启动检查提供足够内存；builder 自身限制为 1 核、1536 MiB。

恢复前核对容器 ID 和当前限制，保留用户在任务期间独立修改过的资源配置。无限 CPU 用 Docker 的 CFS `CpuQuota=-1` 恢复，语义等同原 `0/0`，数值表示可能不同。资源租约保存在 `data/browser-resource-leases/`；面板异常中断时，下次浏览器操作先检查遗留进程并恢复租约，进程未退出则拒绝覆盖。KVM 暂不自动调整内存与 CPU，需另外预留资源。

图形显示使用私有 X11 认证并关闭 TCP 监听，无需完整桌面。原生窗口可直接手动操作；兼容的自动流程仍需先接管，再继续自动流程。关闭窗口、取消或控制管道断开时，槽内 supervisor 终止浏览器进程组，再恢复资源。

远程屏幕支持文字剪贴板：先在槽位网页点击「复制」，再点面板「读取远程剪贴板」，内容会显示在只读文本框中；「复制到本机」支持 HTTPS Clipboard API，也支持内网 HTTP 的选中复制回退。复制失败时可直接在文本框按 Ctrl+C。关闭屏幕、切换槽位或浏览器任务结束会清除面板显示；不写入本地存储、账号池或任务状态，也不自动读取。仅在手动浏览器或已接管的任务中允许读取，限制为 16 KiB 文字。原生模式读取该任务私有显示的 X11 CLIPBOARD；兼容自动流程读取受支持登录页面的剪贴板。

GPT 槽位详情页的「安装浏览器环境 / 卸载浏览器环境」只管理运行文件，不执行账号登录、OAuth 或首次登录解锁。无需绑定账号凭据。槽位必须已运行，无需开启调度，也不会修改调度开关；关机或显式取消会中止维护。维护与登录、远程浏览器共用互斥锁。

安装根据**实际槽位**的 `/etc/os-release`、CPU 架构和系统 Python 版本选择运行包，不根据面板机系统猜测。支持 Ubuntu 22.04（Python 3.10）、24.04（3.12）、Debian 12（3.11）、13（3.13），架构 amd64 / arm64；自定义 Python ABI 不匹配时拒绝安装。实际测试范围另行记录，支持矩阵不代表所有组合均已实测。

面板使用目标 Docker 节点上的临时 builder 下载固定版本 Playwright 1.64.1、Chromium、字体和动态库，并构建图形显示组件，生成匹配系统的包，缓存到面板 `share/kin-mailbox-runtime/managed/`。首次源码构建会下载编译依赖，需要较长时间；这些依赖留在可销毁的 builder，不安装进槽位。缓存通过 SHA-256 校验，同一系统组合可复用。远程节点目前仍通过面板传输运行包，尚未实现节点共享浏览器目录。临时下载代理 `VM2API_BROWSER_BUILD_PROXY` 仅传入 builder，不设置槽位代理；不要把带密码的代理写进公开配置。

运行文件安装到槽位 `/home/kincli/.local/share/kin-mailbox/`，不修改只读系统根目录。全新临时目录内先以槽位用户启动 Chromium，使用内存 HTML、临时 profile 并拦截网页请求，检查成功才替换旧运行文件。失败或取消保留原环境。整个安装过程不读取账号凭据或现有 profile，也不访问登录页面。

卸载仅移除浏览器、venv、显示组件、依赖库等运行文件，保留 `profiles/`、`cache/`、`config/` 和独立存放的账号凭据。升级/重装也保留这些目录。识别到旧 `/opt/kin-mailbox` 环境时会尝试卸载其运行文件，若镜像目录只读则明确报错。卸载后再次点击登录会按需安装，并优先复用匹配系统的已校验缓存。面板仍保留每种系统组合的一份压缩运行包，槽位卸载不删除该共享缓存。

API（沿用面板认证、角色和槽位所有权检查）：

- `GET /api/panel/vms/:id/oauth/login/browser-environment`：只读检测，不启动浏览器。
- `POST .../browser-environment/install`、`POST .../browser-environment/uninstall`：返回 202，轮询上面的状态接口查看结果。

专用测试容器的集成验证（不得指向真实账号槽位）：

```sh
sudo python3 test/manual/mailbox-portable-test.py \
  --image <匹配系统且已安装python3的测试镜像> \
  --bundle <对应系统的r5运行包.tar.gz> \
  --work-dir /var/tmp
```

脚本创建并清理随机命名的专用容器，使用 `network=none`、只读根目录、`cap-drop ALL`、UID 10005、0700 home 和 1536 MiB 内存；验证图形浏览器启动、语言时区、iframe 远程点击和截图、重装保留资料、损坏包及启动失败回退、槽内取消、卸载和重新安装，全程无账号登录。必须在专用 Linux 测试主机执行，不指向现有槽位。`--work-dir` 必须位于磁盘文件系统；将近 1 GiB 的安装文件存入宿主机 tmpfs 会占用容器共享内存配额，导致测试失真。

`test/manual/mailbox-native-test.py` 在同类离线容器内验证原生 X11 输入、中文粘贴、剪贴板、PNG 画面、语言时区，以及虚构 OAuth 回调和错误 state。页面读到的 `navigator.webdriver=false` 来自原生进程，没有脚本改写。另有 `mailbox-native-runtime-test.mjs` 验证真实生产 supervisor 与 Docker 资源恢复链路，要求显式离线开关并拒绝普通或联网容器。
