# v2.5.0 · Codex 6.2 Astra 和 Sol

Codex 网关支持 `gpt-6.2-astra` 和 `gpt-6.2-sol`。在 `/v1/responses` 中使用 `reasoning.effort`，在 `/v1/chat/completions` 和 `/v1/completions` 中使用 `reasoning_effort`；三种接口均接受 `ultra`，支持 JSON 和 SSE。`/v1/responses` 也可通过 WebSocket 调用。

两款模型在回退目录中默认启用。使用已同步账号目录的实例沿用账号返回的型号；重新同步不会覆盖管理员已有的禁用设置。自定义模型映射继续生效，直接请求或通过别名请求已禁用型号都会返回 `model_disabled`。质量任务和槽位测试也可选择 `ultra`。

## 升级与核对

- 控制面镜像：`ghcr.io/zhang2580384/vm2api:v2.5.0`，支持 Linux AMD64 和 ARM64。使用面板更新，或在现有 Compose 配置中将 `VM2API_IMAGE_TAG` 设为 `v2.5.0` 并更新控制面。保留现有环境变量和持久化挂载；本版无数据库迁移。
- Codex 内核附件：`kin-codex-kernel`，5,981,528 字节，SHA256 为 `95727081222f4096e9e63d29e6c9c2e009ff00365a70add30a885063fe7f9993`。15 个固定文件中只有它的内容变更；Claude 内核和 CLI 保留原字节。
- [内核验收](https://github.com/zhang2580384/vm2api/pull/16)在断开外网的容器里运行真实 Linux 内核，用本地上游核对两个型号的出站模型名、推理强度、响应格式与禁用行为。账号能否实际使用某款模型，仍取决于该账号的授权。
