# v2.4.4 · GPT 账号状态可查询，凭证刷新有界等待

遇到请求失败时，先确认账号当前套餐，再分别检查凭证、额度、出口与推理内核。v2.4.4 在所选槽位的原出口上，用现有 Access Token 查询套餐状态，把这些信息直接放进账号详情与概览，减少为了确认套餐而安装和登录浏览器的操作。

## 当前套餐，无需浏览器查询

- **查询账号状态**：在 GPT 槽位概览和账号页手动查询，读取当前 Pro、Plus、Free 等套餐及上游返回的使用限制；不调用模型、不消费重置券。
- **状态随账号显示**：概览、账号详情、弹窗及槽位列表显示套餐确认状态。记录最近查询、上次成功时间，15 分钟前的结果作为历史参考，不继续显示为刚确认。
- **静置仍可手动核对**：关闭接单调度后可显式查询，不开启调度、不启动浏览器，也不创建后台登录任务。
- **更换凭证立即失效**：查询结果绑定当前账号与 Access Token；刷新或重新导入后，旧观察不再用于确认新凭证的状态。查询期间更换账号会丢弃过时结果。

## 刷新凭证，结束无限等待

- 状态查询和 GPT OAuth 刷新对连接及完整响应正文设置超时，避免“已经收到响应头、正文不结束”导致按钮一直转圈。
- 后端账号查询最长 20 秒；前端分别为状态查询和手动刷新设置等待上限，完成后不再等待无关概览请求才结束按钮状态。
- 手动刷新与后台刷新共用凭证旋转锁，避免重复使用同一 Refresh Token；等待期间或请求期间导入的新凭证不会被旧结果覆盖。
- 区分明确的授权失效与临时网关、网络或访问限制，减少把临时失败误报为账号已失效。

## 如何理解查询结果

- **Pro / Plus 等已确认**：上游当前返回对应套餐；是否能够接单仍取决于额度、调度及推理内核。
- **当前为 Free**：当前返回非付费套餐；不据此推测曾经是否订阅、取消原因或具体结束日期。
- **访问凭证过期或被拒绝**：先刷新或重新授权，与订阅是否到期分开处理。
- **查询失败，待确认**：403、429、503、超时和网络错误不能证明订阅到期；保留历史套餐及时间，不自动关闭调度。
- **订阅到期（凭证记录）**：来自凭证签发时记录，续费后可能尚未更新。状态接口未提供新的订阅截止日时不推算，Access Token 到期日也不作为订阅截止日。

本版没有将 Codex OAuth 凭证转换为网页 Session。需要官网 Session JSON 时，仍在已经登录的槽内浏览器打开 Session 页面，再通过远程剪贴板手动获取。本次不增加订阅付款操作，也不将账号查询成功等同于修复所有 `503/no_capacity`。
