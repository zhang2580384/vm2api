# 智能运维：真实质量检测

入口：`/cc#/credentials?tab=quality`。账号凭据沿用原凭据 API，质量运维提供任务、记录、编辑抽屉和完整回答详情。

## 执行与持久化

- 保存不会发送模型请求；“立即检测一次”通过服务器启动真实任务，返回 202，页面轮询结果。账号与槽位合为一个下拉框，模型来自该槽位的受支持模型表。
- 糖果题复用真实 `/v1/responses` 或 `/v1/messages` 链路，以 `x-kin-vm` 指定槽位，保留该槽位的账号和出口。GPT 可选模型默认、low、medium、high、xhigh、max 思考强度；不支持时记录实际错误。Claude 沿用现有协议策略。
- 按用户保存配置至 `data/quality-preview/`，记录至 `data/quality-records/`。原子替换、revision 防覆盖，每用户保留最近 200 条。记录原题、模型、思考强度、来源、完整回答和处理结果。回答保存上限 262144 字符，超出显式提示；判定使用截断前全文。
- 检测频率为整数分钟。每 5 秒检查到期任务，首次启用等待一个周期；重启按最近记录继续，不追补积压。手动检测推迟下一次定时检测。同账号糖果题和探针互斥，全局最多并发 4 个。
- 旧预览任务的启用开关不会直接启动真实任务，需显式重新启用。旧题目和配置保留。
- 每次运行校验账号、权限和模型。已启用的质量运维任务独立于接单调度；槽位关闭调度后，任务仍按设定频率从该槽检测，以便检查账号是否恢复。任务不会开机或登录；槽位仍须已开机。
- 请求实际消耗账号额度。糖果题经过正常转发计费与日志链路；门票探针在指定槽内直接向 Codex 发两次请求，不经过 `/v1` 计费链路，使用量保存在质量记录中。

## 糖果题规则

默认题目逐字采用 sub2 v2.17.3 `backend/internal/service/pelican_scheduled.go` 的 `CandyPrompt`。保存和请求不追加提示词、不裁剪原文；可编辑并持久化，恢复原文按钮只改草稿。

默认按用户要求判断回答是否包含独立数字 **21**，无需裁判模型；排除 121、210、小数、负数。详情可查看完整回答。否定句里出现 21 也可能通过，这是该规则的明确限制。可选严格简短答案模式参考 `candy_answer.go`。修改题意时需考虑固定答案仍为 21；当前不支持任意正确答案配置。

HTTP 200 本身不代表通过。GPT 须有正常完成事件，空回复、流中断、请求失败或错误槽位均为“无法判断”。

## 门票探针与 sub2 的关系

保留 `openai_codex_state_probe.go` 的两次完整请求及核心判据：

1. 第一次无票请求 `chatgpt.com/backend-api/codex/responses`，取 `x-codex-turn-state` 与 `__cflb`、`__oailb` 两枚路由 Cookie。
2. 第二次携原票及这两枚 Cookie，使用新的会话。两次均请求 `Reply with OK.`，保留 `store:false`、`stream:true`、`parallel_tool_calls:true`、`reasoning.encrypted_content`。
3. 两次 HTTP 200 且响应流正常完成后，续接返回不同新票为“检测不通过/疑似降级”；没有新票或沿用原票为“通过”。首次没票、授权失败、429、网络超时、不完整流均为“无法判断”。上报模型仅展示，不参与判定。

这是适配移植，传输层使用**指定槽内 Python、系统 TLS 和绑定透明出口**，并非照搬 sub2 的 Go TLS 指纹。每发总超时 45 秒；禁止重定向、系统代理和宿主机回退。令牌只经 stdin 进入槽位，不落记录、命令参数或日志。原始门票、Cookie 不保存，只记录长度和是否改变。仅支持 GPT OAuth 容器槽位，原生节点暂不支持。

若绑定 SOCKS5 代理只支持域名目标、连接解析后的 IP 会被重置，需在该代理启用现有“域名转发”选项。此选项由操作者按出口兼容性设置，探针不自动切换代理或修改 DNS；关闭时可能出现槽内 TLS 连接提前结束。域名转发只重载相应出口转发器，不重启槽位容器。

独立的槽位服务刷新与滚动维护同样需要加载项目数据库，才能沿用代理池保存的域名转发和全局 DNS 配置。旧版升级脚本可能在面板配置仍开启时将运行出口重建成默认值，表现为重启后探针域名解析或网络请求失败；应检查运行配置与数据库是否一致，不能仅凭此结果判断账号降级。

sub2 的完整票形态实测主要基于长度 780 的门票；此处展示实际长度而不硬编码票长。门票变化属于经验判据，不能证明模型智力或承诺固定模型档位；不实现借票、租用或跨账号路由。

## 异常处理

默认仅记录。选择“检测不通过时关闭槽位调度”后，只有明确 failed 且任务仍启用、配置未改、账号和出口未换、权限仍有效才关闭调度。请求错误或无法判断不会关闭调度；暂停任务的手动检测也不会自动改调度。调度操作失败会保留回答和原判定，并显示处理失败。

糖果题任务可单独开启“检测通过后自动恢复调度”。开启后，失败检测关闭调度时会记录任务归属；后续定时检测仍会执行，只有检测通过、同一任务仍启用且账号与出口未变化时，才恢复该任务关闭的调度。人工关闭、其他质量任务关闭、不可调度故障和维护 hold 都不会被自动恢复。关闭自动恢复可由操作者接管，错误或无法判断结果也不会开回调度。
