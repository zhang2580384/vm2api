# 可启停脱敏插件设计

## Goal

为 **vm2api 当前仓库**设计可开启/关闭的脱敏插件：在 **Node 请求清洗阶段**处理关键敏感元素，提供 **Web 控制面板**管理开关、类别和规则，并完成必要的响应还原。复用 AgentDock/magpie 的 Go 核心行为，不另造正则体系或通用插件平台。本轮交付设计，不实现、不部署。

## Confirmed facts

- 用户明确要求放在当前 vm2api 仓库，接在 Node 清洗链路，并包含 Web 控制面板；`D:\AgentDock\deliverables\redact-analysis` 仅为参考材料目录，不是交付/安装位置。
- 参考材料包含可逆文本/JSON 脱敏、工具参数/签名保护、SSE 还原及可选模型；Go `internal` 限制、进程全局映射和 40-bit 标签等行为不能直接视为多租户安全契约。
- vm2api 的 Claude native、API backend、Codex HTTP/WS、auto 分类请求需要逐路径核对；不能把 Node 中间对象当成最终厂商 wire 的证据。
- 权威资料统一位于 `docs/redaction/`；本地 Trellis 任务仅记录状态并链接到这里。参考源码、ZIP、原校验清单保持原样。

## Requirements

- R1：用当前源码说明参考核心的可复用部分、移植边界和风险，保留准确路径/行号。
- R2：Node 清洗链路提供默认关闭、持久化、可热切换的总开关，支持凭据/秘密、个人信息、自定义词和规则；关闭保留配置，不关闭既有安全清洗，不破坏在途响应还原。
- R3：给出请求与响应的具体挂点，覆盖实际存在的推理路径和分类侧调用；对无法安全支持的路径显式拒绝，不静默发明文。
- R4：明确租户/会话隔离、稳定标签、映射生命周期、重试、缓存、签名、工具调用和流式收尾的契约。
- R5：**Web 控制面板是必交付范围**：现有设置 → 协议增加内容脱敏区，沿用管理 API、草稿/保存/放弃/刷新；区分未保存值、已保存策略与运行状态，失败保留草稿。不新建插件安装或脚本运行平台。
- R6：在当前仓库 `docs/redaction/` 交付 `design.md`、`implement.md`、源码证据与验收矩阵；仅以合成输入验证参考核心，不使用真实凭据/请求、外部模型或生产服务。

## Acceptance Criteria

- [x] A1（R1）：关键结论有当前源码依据，已区分现有能力、设计建议和未验证范围。
- [x] A2（R2、R5）：Node 清洗阶段的开关、关键元素范围和处理顺序，以及 Web 字段、权限、状态、保存失败/刷新行为已明确。
- [x] A3（R3、R4）：初次清洗与最终发送复核的数据流完整；签名/缓存、SSE/WS、工具参数、租户与历史恢复限制有可验证决策。
- [x] A4（R6）：执行一次隔离的真实 Go 核心合成 smoke，记录输出和边界，不把它称作 vm2api 插件端到端已实现。
- [x] A5（R6）：实施顺序、验收场景、回滚与阻断条件可供后续实施使用；不启动实现阶段。
